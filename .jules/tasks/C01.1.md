### Log de Pesquisa (2024-08-09):

**1. Documentação Oficial Next.js (v15.3.4, acessada em 2024-08-09):**
   - **URL:** `https://nextjs.org/docs/app/building-your-application/routing/route-groups`
   - **Principais Pontos:**
     - Route groups `(folderName)` são para organização e não afetam o path da URL.
     - Permitem múltiplos root layouts, o que é um caso de uso chave para este projeto.
     - **Ressalva Principal:** Navegar entre rotas que usam *diferentes root layouts* (ex: `app/(shop)/layout.js` vs. `app/(marketing)/layout.js`) causa uma **recarga completa da página (full page reload)**. Isso é uma consideração de performance e UX.
     - Rotas em grupos diferentes não devem resolver para o mesmo URL path (risco de conflito).
     - Se múltiplos root layouts são usados sem um `layout.js` global em `app/`, a home page (`/`) precisa ser definida dentro de um dos grupos.
   - **Conclusão Preliminar da Documentação:** A principal "limitação" documentada é a recarga completa da página entre diferentes root layouts. O projeto já usa route groups com layouts próprios, então essa recarga já deve ocorrer.

**2. Pesquisa de Issues no GitHub (vercel/next.js):**
   - **Query:** `is:issue route group layout reload` (e variações)
   - **Issue #52879: "Full reload of page with multiple root layouts files" (Open, Bug, Jul 2023)**
     - Confirma que o "full page reload" é um comportamento conhecido e reportado como bug/problema pela comunidade.
     - Link: `https://github.com/vercel/next.js/issues/52879`
   - **Issue #58597: "Global CSS not removed between app router pages" (Open, Bug, Nov 2023, Tags: CSS, Route Groups)**
     - Descreve um problema onde CSS global (importado no root layout de um grupo) pode não ser adequadamente removido ao navegar para uma página em outro grupo de rota com um root layout diferente. Isso pode levar a estilos conflitantes.
     - Este é um ponto de atenção importante se cada seção do app (marketing, admin, etc.) tem estilos globais que não deveriam vazar.
     - Link: `https://github.com/vercel/next.js/issues/58597`
   - Outras issues encontradas eram mais específicas para `Intercepting Routes`, que podem ou não ser relevantes dependendo do uso no projeto.

**3. Análise Inicial das Descobertas:**
   - A "limitação da ferramenta" mencionada na tarefa pai `C01` pode se referir principalmente ao **full page reload** entre seções com root layouts diferentes e/ou ao **vazamento de CSS global** entre esses layouts.
   - O projeto já usa a estrutura de route groups com layouts individuais (ex: `app/(marketing)/layout.tsx`, `app/(admin)/layout.tsx`). É crucial entender se o comportamento de recarga completa é aceitável e se o problema de vazamento de CSS está ocorrendo ou foi mitigado.
   - A versão do Next.js do projeto é ~14.2.4. As issues mencionadas são de 2023, então provavelmente são relevantes para esta versão.

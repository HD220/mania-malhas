### Síntese e Plano de Ação (2024-08-09):

**1. Informações Consolidadas:**
   - **De `C01.1` (Pesquisa Route Groups):**
     - Route Groups são adequados para múltiplos layouts raiz.
     - Principal ressalva: "Full page reload" ao navegar entre seções com diferentes layouts raiz (Next.js docs, GitHub Issue #52879).
     - Potencial problema: Vazamento/persistência de CSS global entre diferentes layouts raiz de grupos (GitHub Issue #58597).
     - O projeto já utiliza Route Groups (`(admin)`, `(auth)`, `(main_app)`, `(marketing)`) com `layout.tsx` próprios.
   - **De `C01.2` (Avaliação de Layouts Atuais):**
     - `RootLayout` global (`app/layout.tsx`) fornece base HTML, tema, toaster.
     - Layouts de grupo (`(marketing)`, `(admin)`, `(main_app)`) definem estruturas de página quase completas. `(auth)` é minimalista.
     - A estrutura atual é uma aplicação válida de Route Groups.
     - Preocupações reiteradas: "full page reload" e potencial vazamento de CSS.

**2. Análise de Viabilidade:**
   - **Atendimento aos Requisitos:** Route Groups já estão atendendo à necessidade de layouts distintos. A questão é a otimização e mitigação de efeitos colaterais.
   - **Limitações e Workarounds:**
     - **Full Page Reload:** Característica do design do Next.js com múltiplos layouts raiz. Aceitabilidade depende da UX.
     - **Vazamento de CSS Global:** Preocupante. Mitigações incluem escopo de CSS, minimização de CSS em `globals.css`, e verificação do comportamento real no projeto.
   - **Prós de Continuar:** Organização clara, layouts distintos, idiomático no Next.js.
   - **Contras de Continuar (sem mitigação):** UX afetada por recargas, risco de conflitos visuais por CSS.

**3. Decisão e Plano de Ação:**
   - **Decisão:** Continuar utilizando Route Groups. Investigar e mitigar os efeitos colaterais conhecidos.
   - **Próximas Sub-Tarefas Propostas (a serem criadas após esta síntese):**
     - **`C01.3.1`:** Investigar e Testar Vazamento de CSS Global entre Route Groups (Complexidade: 1).
     - **`C01.3.2`:** Avaliar Impacto na UX do "Full Page Reload" entre Seções (Complexidade: 1).
     - **`C01.3.3`:** (Condicional a C01.3.1) Mitigar Vazamento de CSS Global (Complexidade: 2).
     - **`C01.3.4`:** (Condicional a C01.3.2) Otimizar Experiência de Transição entre Seções (Complexidade: 2-3).
     - **`C01.3.5`:** Documentar Diretrizes de Layout e Route Groups para o Projeto (Complexidade: 2).

**4. Atualização da Tarefa Pai `C01`:**
   - `C01` permanecerá `Subdividido`. Após a criação formal das sub-tarefas `C01.3.x`, a nota em `C01.md` deverá ser atualizada para listá-las como as novas etapas de trabalho para "Monitorar viabilidade de Route Groups".
